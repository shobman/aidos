# Migration v2.0.0 → v3.0.0

## Summary

v3.0.0 is a windback. AIDOS narrows to what it is good at — warranting and defining
work before development starts — and stops reaching into execution.

Removed: the `aidos-breakdown` and `aidos-fanout` skills and the Breakdown rubric;
the Overflow Log; the central Issues Log; the Meeting Minutes template; both
connectors (GitHub MCP, Confluence Publish). AIDOS ships two components — the
Framework and two Skills.

Added: decision records carry a basis, evidence, a falsifier, a blast radius and a
test-impact flag (Core C15), every
artifact states the decision it is reconciled to (Core C16), and the Auditor runs a
second **readership pass** (`rubrics/readership.md`) that asks only whether the
artifact can survive being read by the people who must act on it.

Reshaped: the Solution moves from workflows to independently valuable user stories.
The Tech Design gains a Deviations and Debt section — it is the consequential HOW,
not a complete account of the code, and it is corrected as the build teaches. The
Testing artifact becomes a strategy and an evidence standard; per-item acceptance
criteria are a projection onto the work item, not content it holds.

Unchanged: all three scales (Epic, Feature, Story), the four artifacts, the Problem
artifact, builder/auditor separation, and the `.aidos/` convention — which is now
explicitly optional. Nothing in AIDOS says artifacts must live in git.

**This migration is best-effort and offered, not forced.** An artifact that stays on
v2.x keeps its `AIDOS Version` stamp and remains valid under the version it was
built with — the v3 Auditor will not assess a v2.x artifact against v3 rubrics; it
recommends migration and stops. Migrate artifacts as you reopen them for active
work. Steps 6, 7 and 8 are content-level rewrites: apply them with the human in the
loop, presenting diffs before writing, per the Builder's per-file upgrade flow.

## File renames

None.

## Content changes

Apply to one artifact file at a time, in this order.

### Mechanical — apply directly, show the diff

1. **All artifacts — decision log.** Convert the `## Decisions` table from the v2
   columns `| # | Source | Issue | Resolution | Decided By | Date |` to the v3
   columns `| # | Decision | Basis | Test impact | Decided by | Date |`. Map them
   the same way every time:

   | v2 column | v3 destination |
   |---|---|
   | `#` | `#` — unchanged, never renumber |
   | `Resolution` | `Decision` |
   | `Decided By` | `Decided by` |
   | `Date` | `Date` |
   | — | `Basis` → `unrecorded` |
   | — | `Test impact` → `unassessed` |
   | `Source` | the decision's detail block |
   | `Issue` | the decision's detail block |

   `Source` and `Issue` lose their columns but not their content. Carry both into
   that decision's detail block, creating one if the artifact has none:
   `**Rationale:** Migrated from v2 — raised in <Source>; closed issue <Issue>.`
   `Issue` matters most — it records which issue the decision closed and is the
   only link back to it.

   Do not guess a basis or a test impact. Core C15 permits `unrecorded` /
   `unassessed` for exactly this case — a decision taken before v3.0.0 and carried
   across by migration — and scores it a **Partial**: never a Pass, never a Fail.
   Retro-fitting a basis onto an old decision is fabricating provenance, which is
   worse than admitting it was never captured. A decision taken *after* migration
   has no such latitude. The Partial is resolved by the human directing the audit,
   not by inventing a basis: they may supply the real basis for decisions still
   load-bearing, or accept the Partial and leave the rest flagged.

   Superseded decisions already present stay in place — never delete one.

2. **All artifacts — metadata.** Add two lines after the last link line in the
   metadata block — `**Parent:**` in a Problem, `**Problem:**` in a Solution,
   `**Solution:**` in a Tech Design, `**Solution:**` (which follows
   `**Tech Design:**`) in a Testing artifact:

   - `**Reconciled to:**` — the highest-numbered decision in this artifact's own
     log, or `—` if the artifact has no decisions.
   - `**Walked through:** —` — always the em dash on migration. Readership R4
     reads this line as the artifact's own statement of whether someone other than
     the author has explained it back, and `—` says truthfully that this has not
     happened yet. Do not omit the line: `—` is an absence the auditor can score,
     whereas an artifact carrying no such line at all is an undefined state.

   Then stamp `**AIDOS Version:** 3.0.0`.

3. **All artifacts — Latest Updates.** Add a `## Latest Updates` section
   immediately after the metadata block and before the `---` rule, with the
   columns `| Date | What moved |`, newest first. Seed it with exactly one row
   recording this migration — e.g. `| <today> | Migrated to AIDOS v3.0.0; see
   Decisions (basis and test impact now recorded) and the new sections. |`. The
   section is Readership R3's evidence, so a migrated artifact must have it; do not
   backfill a change history from the file's git log or from memory — two or three
   rows is the working size, and the migration row is the only one that is known.

4. **Overflow Log — dissolve and delete.** For each item by status:
   `HARVESTED` — already placed in an artifact; delete the row.
   `DISCARDED` — the rationale is already recorded; delete the row.
   `PARKED` / `BACKLOG` — move to the team's own backlog, or into the artifact that
   owns the concern if one does. Present the list to the human before moving
   anything; these are the items someone deliberately kept. Delete
   `overflow-log.md` only once the list is empty.

5. **Central Issues Log — dissolve and delete.** Each open issue returns to the
   `## Issues` section of the artifact it belongs to, keeping its status
   (OPEN / SOCIALISE / ESCALATE) and any decision packet. Resolved entries are
   already in their artifact's Decisions table — delete those rows. Delete
   `issues-log.md` once empty.

### Confirmation-gated — propose, do not write until the human accepts

6. **Solution artifacts (and the Solution section of a combined `feature.md`).**
   Section moves — renames, additions, and one reordering:
   - Renamed: `## Solution Overview` → `## Solution Thesis`; `## Actors` →
     `## Actors and Authority`; `## Workflows` → `## User Stories`;
     `## Edge Cases` → `## Scenarios`.
   - New: `## Problem Coverage`, placed after `## Scenarios`.
   - Reordered: `## Minimum Viable Slice` moves up. v2 places it after
     `## Constraint Compliance`; v3 places it after `## Problem Coverage` and
     before `## Alternatives Considered`.

   The resulting v3 order is: Solution Thesis, Scope Boundary, Actors and
   Authority, User Stories, Scenarios, Problem Coverage, Minimum Viable Slice,
   Alternatives Considered, Dependencies, Migration and Transition, Constraint
   Compliance, Issues, Decisions, Auditor Notes.

   The content rewrite is the substance, not the renames:
   - **Workflows → user stories.** Each workflow becomes one or more stories in the
     form `As a <person>, I can <capability>, so that <valuable outcome>`, titled by
     the user outcome. A story must be worth delivering on its own. Where a workflow
     decomposes into several stories, propose the split and let the human accept it
     — a workflow that resists splitting usually means the value is genuinely one
     story with several steps, and the steps become prose inside it.
   - **Edge cases → scenarios.** Keep Given/When/Then only where the behaviour or an
     authority boundary would otherwise be ambiguous. Convert the rest to prose.
   - **Actors and Authority.** Add who may originate work, make judgments, perform
     execution, accept outcomes, and close work. If the artifact does not say and
     it cannot be inferred, add an Issue (status OPEN): "S8 — authority boundaries
     not stated; needs stakeholder input." Do not invent them.
   - **Problem Coverage.** Map each need stated in the Problem to the stories that
     answer it. A need with no story, or a story with no need, is a Bug — record it
     in `## Auditor Notes` rather than silently adding or deleting content.

7. **Tech Design artifacts (and the Tech Design section of a combined file).**
   Add `## Deviations and Debt` after `## Transition Strategy`. If the build has
   already started, ask the human what has departed from this design and what debt
   was taken, and record it with the decision that authorised each departure. If the
   build has not started, write "No deviations; implementation not begun."

8. **Testing artifacts (Test Strategy / Test Plan / Acceptance Criteria).**
   Add `## Evidence Standard` — what counts as proof, what does not, and who
   produces the independent check. If the artifact does not say, propose the v3
   default and let the human confirm it: re-runnable beats static, and evidence
   produced by the same run that built the code is not an independent check.

   Reframe `## Coverage Map` from a per-assertion traceability matrix to coverage of
   the Solution's goals and the Tech Design's constraints by a stated approach to
   proving each. Per-item acceptance criteria drop out of the artifact — they belong
   on the work item. Present what is being removed before removing it; some of those
   rows are the only place a requirement was written down, and those move to the
   card rather than disappearing.

### Housekeeping — no artifact content involved

9. **A decomposed tree stays valid.** Repos that ran `aidos-breakdown` keep their
   Feature and Story artifacts; each migrates independently as it is reopened. The
   Breakdown rubric no longer exists, so any open Bug or Risk in an `## Auditor
   Notes` section citing it — its Bugs B1–B6, or its own Risks R1 (Feature
   coherence) and R2 (Architectural dependencies declared) — is closed as no
   longer assessed, with that reason recorded. Those are **not** the Readership
   rubric's R1–R4, which are live in v3: a finding citing Readership R1–R4 stays
   open. Do not re-audit the tree's shape.

10. **`.aidos/manifest.json` is inert.** Its `write` strategy and `publish.*` sections
    configured connectors that no longer exist. The file can be deleted; if it is
    kept, nothing reads it.

## Metadata changes

- `**AIDOS Version:**` → `3.0.0`.
- New required field `**Reconciled to:**`, after the last link line in the metadata
  block (`**Parent:**`, `**Problem:**`, `**Solution:**` or `**Tech Design:**` /
  `**Solution:**`, depending on the artifact).
- New required field `**Walked through:**`, immediately after `**Reconciled to:**`.
  Set to `—` on migration.
